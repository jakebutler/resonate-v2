# Visual admission and compatible containment

New server visual work requires `EDITORIAL_VISUALS_ENABLED=1`; absence, `0`, and unsupported values pause admissions. The frontend separately requires `NEXT_PUBLIC_EDITORIAL_VISUALS_ENABLED=1`. Neither flag qualifies a live provider, supplies a cost bound, starts a dispatcher, or grants image approval. Paid routes remain unqualified and paused. Ordinary offline tests explicitly enable the server flag.

The only absent-flag exception is the existing exact anonymous loopback fixture boundary: actor `visual-rehearsal-only`, mode `local-offline`, deployment `anonymous-agent`, Convex URL `http://127.0.0.1:3210`, site URL `http://127.0.0.1:3211`, matching or absent cloud URL, and the zero-cost `offline-fixture` route. Explicit `0` pauses even that fixture. There is no server `NODE_ENV` bypass. Fixture auth and configuration must remain local.

Authentication, ownership, writer role and lifecycle checks precede the admission guard. Planning, profiles, reference uploads, linked import, figure changes, hero selection/export/approval and new publication transport are paused. Immutable inspection, cancellation, recovery, owner reconciliation, late trusted settlement, stale-input maintenance and retained PR status refresh remain available. A pause during reserve or claim throws outside cancellation catches, preserving existing reservations. Late completions retain usage and bytes but cannot select a new hero while paused. Terminal lifecycle states and every recorded PR URL, branch or status require a separate publishing transition before figure, hero or linked-evidence writes. Legacy reschedule or metadata edits retain that authority, including open, draft, closed and partial historical records.

Final visual approval, new publication snapshots and trusted PR result recording also reject terminal lifecycle and any recorded PR identity. The final review query reports that gate. If a merge arrives after transport begins, the action retains the new remote PR in its structured review error and preserves the prior saved merged PR; no automatic retry occurs.

Containment uses a compatible forward build: set the server flag to `0`, build the frontend with its public flag `0`, and retain the additive schema, indexes, ownership, approval, publication and accounting guards. Check actual target identity and read back both deliveries. Keep uncertain reservations and receipts intact. A blind baseline backend/schema rollback can strand persisted state; an old frontend can omit current publication controls. Vercel routing rollback requires a separately verified compatible candidate and actual project eligibility.

## Older open composers

The legacy v2 storage read omitted `postId`. Only `v2Storage.getFileUrl` enables a read-only server lookup when that argument is absent: the authenticated user and exact hero storage ID must match saved posts through an additive compound index. At most two matches are permitted and all matching brand memberships must be present. Classified reference, version/export and registered-upload ownership checks run first and are terminal. Foreign and orphan files, an invalid explicit context, missing memberships and ambiguous matches remain denied. Shared legacy reads and attachment mutations do not receive this fallback. Existing bearer URLs are not retroactively revoked.

The deprecated `v2Storage.generateUploadUrl` symbol authenticates and returns an explicit reload error without issuing a URL or writing anything. The updated composer uses owned-byte `uploadImage`. Already-issued older upload URLs can leave an unregistered unsaved blob; those blobs remain inaccessible through the new ownership rules and require reload and deliberate re-upload. This is a safe reload boundary, not full older-client upload compatibility.

Public-interface RED/GREEN tests cover the admission flag, strict fixture boundaries, unchanged reservations during pause, recovery and late settlement, merged lifecycle guards, exact dispatch schedule/intent CAS, and older-client storage behavior. Separate action tests prove pause occurs before mocked GitHub transport. All tests use fictional data and make no paid calls. These repairs need fresh independent review and exact-candidate CI.

This is backup verification, not a restore rehearsal. Production named-variable reads found the server admission and fixture flags absent; masked Vercel inspection found the frontend admission and fixture/auth-bypass flags absent. Delivery still requires current identity, additive production dry run, compatible ordering, exact reviewed candidate checks and live default-off readback. Enabling live work additionally requires provider qualification and human approvals under the coordinator contract.

Production routing must deliver this backend before the new frontend. Ordinary composer and publication routes use changed API arguments/functions outside the visual UI flag. Keep the existing frontend served until exact merged backend success and compatibility readback; only then route the same qualified frontend commit. Independent automatic Git deliveries do not guarantee that ordering.
