# Server publication actions

`visualPublication.createPr({postId})` is a Node action. The caller supplies only the owned saved post ID. Authentication runs before the action reads one `publishing.getPostForPublication` snapshot. That query is responsible for ownership, brand access, approved article and publishing intent, current evidence and hero approval, and publication lifecycle eligibility.

The action derives title, body, first comment, excerpt, author, category, tags and slug from the saved post. Date and time come from the approved intent, falling back to the saved post; an absent date uses the server's current UTC day. Timezone comes from the intent, then the post, then UTC. Frontmatter uses `status: draft`, `scheduleTrigger: pr-body`, `featured: false`, and no subtitle.

The approved hero must exist. Its exact stored export bytes must be below 150,000 bytes, match the approved SHA-256 and export metadata, and pass `prepareBlogPublication`'s actual WebP dimensions and format validation. The manifest carries provider, model, quote provenance, qualification, approving actor and approval time. Every figure carries the same snapshot's immutable specification, exact SVG bytes and hash, renderer and data/presentation signatures, article hash/fingerprint, source revision proofs, and accepting actor/time. `prepareBlogPublication` independently revalidates those proofs and exact placements.

The action calls `prepareBlogPublication` with its default production policy before GitHub transport. Offline fixture/contract provenance cannot reach GitHub. The separate guarded local reader harness may explicitly permit fictional fixture preparation; these public actions have no such option.

After `createBlogPostPR`, the action calls internal `publishing.recordVisualPublicationPr` with the GitHub result, `expectedArticleSignature = JSON.stringify({title,content,linkedinFirstComment: post.linkedinFirstComment ?? ''})`, and the snapshot's `reviewSignature`. The mutation rechecks saved approval and ownership atomically. A successful action returns `{prUrl,branchName,sanitizedResponse,recorded:true}`. If recording fails after transport, a structured `ConvexError` retains that result with code `VISUAL_PR_RECORDING_REQUIRES_REVIEW` and an inspect-before-retry message. The action never repeats transport automatically. Consumers must retain and display that error rather than treating it as permission to retry. External PR creation and Convex recording are separate transactions; the retained error is the explicit recovery boundary.

`visualPublication.refreshPr({postId})` authenticates, loads the direct owned post document from `publishing.getVisualPublicationPr`, fetches status for that saved PR URL, and records the fetched status through internal `publishing.recordVisualPublicationPrStatus` with `expectedPrUrl`. Its result is `{prUrl,prStatus,prNumber,recorded:true}`, with `prNumber` nullable. A saved URL change before recording rejects the operation without repeating the fetch. The root-owned query/recording functions must enforce the configured repository URL and ownership contracts. Browser callers cannot provide a PR URL, publication body, frontmatter, visual manifest or status.

## Offline verification

Public action tests use `convex-test`, actual stored WebP bytes and the real pure publication validator. GitHub creation/status transport is mocked. Trusted publication snapshots and internal recording responses are mocked for successful transport and stale-recording cases; a separate test uses the real publishing query to verify owned-post/approval denial. The synthetic qualified snapshot fields exercise manifest wiring and do not qualify any provider or real image.

Behavioral receipts on 2026-09-30: initial fixture rejection test RED at 13:04:02 UTC (missing action), GREEN at 13:05:37 UTC; refresh test RED at 13:09:03 UTC (missing export), GREEN at 13:10:04 UTC. All eight owned tests passed at 13:14:29 UTC. Scoped ESLint and the repository production typecheck passed. The broader Convex check includes existing test type errors outside this slice; it reported no diagnostics for either new publication file. Regression checks cover exact saved metadata and evidence, one snapshot, anonymous/foreign/viewer denial, guessed IDs, client field rejection, missing/altered hero bytes and metadata, retained post-transport CAS failure, and refreshed URL CAS failure. No credentials, real GitHub requests, paid model calls, publication, or deployment were used by this slice. Local Convex registration/codegen and integrated review remain coordinator responsibilities.
