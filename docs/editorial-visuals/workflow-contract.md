# Durable editorial visual workflow

Local implementation on `feat/editorial-visual-generation`, based on `b8b6e44baab1d728f6a2267e043acc64b03bec66`. No paid requests, live credentials, publication, commits, or pushes were performed by this worker.

The workflow uses additive Convex tables registered by the coordinator. Only owned saved `corvo-blog` posts are eligible; membership is required, and only owner/editor roles can mutate. Published, submitted, and PR-created posts require a separate publishing transition before feature edits. Profiles, ordered image references, exceptions, lesson revisions, article contents, selected story, prompt, and edit parent are pinned into attempt inputs. Attempts retain full canonical input signatures: an operation key is scoped to post and stage and cannot be reused with changed inputs.

## Public API

- `get({postId})` returns the current exact `articleSignature`, durable state, bounded attempt/plan/version/reflection history, shared monthly budget and usage. Versions expose authorized `url` and `exportUrl`; dispatch claim keys are omitted. The snapshot contains the latest eight attempts/versions and four plans/reflections, plus an older selected version or active attempt when needed. `getVersionHistory({postId,cursor:null|string})` retrieves pages of ten versions with authorized URLs.
- `acknowledgeCostOverrun({brandId,expectedOverrunMicros})` requires the owner to review the exact sum of unacknowledged overrun and positive late-receipt adjustments before admissions resume. Historical actual spend and overrun totals are retained and an audit event records acknowledgment.
- `setMonthlyBudget({brandId,limitMicros})` requires a brand owner. USD costs use integer millionths of a dollar; no default allowance is inferred.
- `requestPlan({postId,operationKey})` queues article-bound planning against the configured profile and relevant director lessons. First entry creates durable visual state and clears legacy final post approval. Subsequent plans retain selected/approved assets.
- `selectScene({planId,sceneIndex,refinedScene?})` accepts only complete three-scene plans. A full explicitly authored refinement records the author's selected story. `refinedScene` has `title`, `subject`, `metaphor`, `action`, `reveal`, `articleConnection`, and an exact `articleAnchor`.
- `requestGeneration({postId,operationKey,expectedArticleSignature,expectedPlanId,expectedSceneIndex,expectedRefinedSceneSignature,prompt?,modelOverride?,providerOverride?})` first compares the exact viewed article and scene selection, before any queue or budget side effect. `expectedRefinedSceneSignature` is `stableInputSignature(state.refinedScene ?? null)`. It pins the selected scene and original profile revision. `prompt` supplies production instructions appended to the explicit core story, profile guidance, exception, and applicable lessons. It cannot replace the stored core story. Raw requested size is 1536×1024; export is 1600×900.
- `requestEdit({postId,operationKey,feedback,expectedArticleSignature,expectedPlanId,expectedSceneIndex,expectedRefinedSceneSignature,expectedParentVersionId,modelOverride?,providerOverride?})` requires the same viewed selection proof plus the displayed selected parent version. It uses that immutable version's stored image as parent. Model and provider remain distinct, and the model remains unchanged by default. Model-scoped lessons are removed when their model/provider no longer match. Original author production instructions and ordered earlier feedback remain in subsequent edit prompts; latest feedback takes precedence. Their serialized input is subject to the same byte bound. Bounded legacy history is resolved through owned parent versions.
- `selectVersion({postId,versionId})` retains all lineage. Selecting a different version clears final post approval.
- `cancelQueuedAttempt({attemptId})` cancels only work not dispatched and releases any reservation. The brand owner can release another author's queued work after a lifecycle transition; the original request author with current owner/editor/viewer membership can release their own work. Unknown roles fail closed. It cannot release running or uncertain work. A new explicit action key is necessary after cancellation/failure.
- `getAttemptRecovery({attemptId})` is an owner-only recovery read: attempt/post/brand/actor, stage/status/updatedAt, reservation, receipt, diagnostic reason, dispatch time, and the declared running-lease expiration when present. It never exposes the dispatch claim.
- `recoverRunning({attemptId,expectedUpdatedAt,reason})` lets a brand owner move an orphaned running attempt to uncertain only after its fifteen-minute dispatch lease expires. The exact inspected state and attestation are checked and audited; the reservation remains retained. The exact attestation is idempotent. Recovery never dispatches, releases usage, or retries.
- `reconcileUncertain({attemptId,expectedUpdatedAt,reason,actualMicros,usageKind,usageReceipt})` is explicit owner-attested recovery of an uncertain outcome. It checks the exact inspected state, records reported or estimated existing usage, releases the reservation, clears the active image slot, audits the owner, and marks the attempt failed. The receipt is owner-attested evidence, not live provider qualification. The exact attestation is idempotent; changed reuse rejects. It never dispatches or retries.
- `approveHero({postId,versionId,alt,expectedExportHash,expectedExportMetadataSignature,expectedArticleSignature})` approves only the selected, prepared export preview and exact reviewed article context. The actor comes from auth. Changed preview/context is rejected. The metadata signature is `stableInputSignature(version.exportMetadata)`. The exact reviewed article is retained in `approvedArticleSignature`; conservative relevance normalization is a separate `approvedRelevanceSignature`.
- `confirmRelevance({postId,versionId,expectedArticleSignature})` records an explicit human confirmation for the current selected version/current reviewed article context. It is separate from asset and final post approval.
- `getPublicationVisuals({postId})` rechecks the selected approval, relevance, stored export bytes, and the version's completed attempt and bound stored quote. It returns exact hash/alt/presentation/storage URL plus persisted `approvedBy`, `approvedAt`, `provider`, `model`, `quoteProvenance`, and `qualification: 'offline-fixture' | 'offline-contract' | 'live-receipt'` from the same snapshot. Offline qualification remains explicit for external publication gates. It returns null for legacy posts that have never entered the workflow.

## Internal boundaries

Only internal mutations can reserve quoted costs, claim dispatch, mark uncertainty, process provider receipts, or complete outputs. Public owner recovery can attest and settle existing uncertainty; it cannot complete assets or authorize dispatch. Every stage (`planning`, `generation`, `edit`, `reflection`) and provider consumes the same brand/month aggregate. Reservation checks and aggregate updates occur in one Convex transaction; claims transition queued work to running exactly once. An uncertain dispatch keeps its reservation and cannot be retried/cancelled. Explicit owner attestation or a retained trusted provider receipt can reconcile it without redispatch. Receipt reconciliation moves reserved usage into either reported or estimated actual usage. Idempotent completion rejects a changed result under the same claim.

`reserveAttempt({attemptId,quoteId})` reads `v2VisualDispatchQuotes`; the caller cannot supply costs or provenance. The quote binds the exact canonical input, stage, provider/model, maximum, qualification, and cost-bound evidence. `claimAttempt` rechecks the stored quote, exact pins, ordered owned references and storage hashes, raw edit parent, and membership before changing queued work to running. Invalid permissions, lifecycle, exact article context, stored pins/bytes, or a previously reserved quote cancel before dispatch and release any reservation. Generation and edit share one dispatch lane and require the active image slot to match the attempt. Current live provider capabilities have no qualified route with a reliable upper bound: every `live-receipt` quote fails closed for every stage. There is no dispatcher in this module.

`registerLocalFixtureQuote` is internal and cannot grant live qualification. The fixture registry always requires the explicit local mode/deployment flags, exact loopback backend URL, exact loopback system site URL, absent-or-exact loopback system cloud URL, fictional actor `visual-rehearsal-only`, provider/model `offline-fixture`, and zero micros; `NODE_ENV=test` grants no bypass. Ordinary tests insert separately marked `offline-contract` rows through the trusted in-process Convex-test boundary; that qualification only works with test mode and both deployed system URLs absent. The registry cannot mint it. [Convex documents that system URLs are always available in deployed functions](https://docs.convex.dev/production/environment-variables); [custom domain settings can override their values](https://docs.convex.dev/production/custom-domains), so the fixture CLI independently verifies the actual anonymous loopback instance before admin calls. See `fixture-rehearsal.md`. No environment branch enables a live provider. Planning and reflection have the same running/uncertain stage guard as image work. A newly approved reflection may queue behind uncertainty without undoing valid asset approval; it cannot reserve or claim.

Reconciliation records actual spend even when it exceeds the reservation. Excess charges mark the attempt/month and block brand admission until explicit owner acknowledgment. A trusted provider receipt arriving after owner attestation is recorded separately in the attempt's late-receipt fields, exactly once. The reported-minus-attested delta adjusts the original month, including refunds; positive deltas and additional overrun block admissions until owner acknowledgment. Late image bytes retain a diagnostic storage ID but create no selectable version. `completeImage` and `completePlan` return null for these owner-reconciled late outcomes. Stale queued reflections cancel with reservation release before dispatch; approval proactively releases them in batches of eight, with bounded release-only scheduled maintenance for remaining rows. A late paid stale reflection settles as failed with its receipt, preserving the charge and creating no lessons.

`completePlan` retains invalid/duplicate/incomplete output with reasons; only three complete materially distinct scenes are selectable. The deterministic gate requires exact article anchors and detects high lexical overlap. Semantic distinctness and relevance remain responsibilities of the trusted planner and human review; passing this structural gate is not semantic proof.

`completeImage` binds returned storage bytes/hash/size/content type to its attempt, provider/model, submitted prompt and optional provider rewrite. Results persist independently of the composer. Versions retain immutable image bytes and parent/feedback history. Previously bound reference, raw-version, or export blobs cannot be reused as a different completion. An unbound registered upload must also match the attempt owner and brand. Completion records the charge and immutable bytes even if more than 512 approved intents defer selection. The result remains unselected with a diagnostic reason until intent reconciliation. Auto-selection requires current author edit permission and the exact queued article, selected version, plan, scene index, and refinement signature. A changed selection or revoked actor leaves the charged bytes retained and unselected. The matching active slot always clears. Scene changes cancel an undispatched active image attempt and release its reservation.

The coordinator's Node action calls `getVersionForExport({userId,versionId})` and `recordHeroExport({userId,versionId,sourceSha256,exportStorageId,exportHash,exportMetadata})`. Export metadata is `{width:1600,height:900,bytes:<150000,format:'webp',crop:string}`; source/export hashes must be canonical lowercase SHA-256 hex. Changed export bytes/presentation clear that version's human approval and clear final post approval only for the currently selected hero. The return value is `{exportStorageId,exportHash,exportMetadata,reused}`. Identical bytes/metadata retain a verified existing storage ID and approvals; if the retained blob is missing or invalid, identical verified replacement bytes bind a new ID without clearing the reviewed bytes/presentation approval, with an audit event. The coordinator deletes the newly generated duplicate blob only when its ID differs from the retained ID. Both helpers independently rederive the inherited authenticated identity and reject a mismatching `userId` argument and forbidden current role/lifecycle. Author identity is taken from the authenticated action, never a public completion request.

Approval after one or more lineage feedback rounds queues a reflection bound to the original inputs, ordered immutable version history, final approved export/presentation/alt, and exact reviewed article. Reflection inputs reference that history rather than duplicating all instructions. The internal `getReflectionContext({attemptId})` resolves bounded full context for trusted processing only. Before reserve and claim, the server verifies complete lineage, original root ID with null parent, ordered adjacency, final version ID, exact approved presentation/alt, and the stored canonical byte count. `claimAttempt` returns optional `reflectionContext:string` atomically for reflection dispatch. Completion rechecks the approved alt and presentation as well. Missing or incomplete legacy context cancels before spending. Internal reflection keys permit up to 512 characters; public action keys remain limited to 120. An additive optional SHA-256 approval signature/index finds exact active/completed reflection history beyond the most recent eight records, followed by full context comparison; recent legacy records retain a bounded fallback. Reapproval after stale cancellation or failure creates a fresh reflection. Initial approvals have no reflection. Exhausted budgets leave reflection queued while preserving valid hero approval. `completeReflection` stores an untested candidate prompt and immutable scoped lessons; it never replays the prompt. Every generated lesson stays post-scoped, including model output that requests brand-wide scope. Brand profile changes remain proposals; broader lesson promotion has no API and requires a separate authenticated review of evidence. Model scope binds the final actual provider/model. Profile changes remain proposals and never mutate a brand profile.

The resolved ordered lineage includes every version's exact full submitted `input`, retained `revisedPrompt` (null when absent), submitted prompt, feedback, parent ID, actual provider/model, storage ID and image hash. The root's full `originalInput` also remains explicit. Each raw input retains its own article, immutable profile/lesson/exception/reference pins, ordered references, selected scene, queue selection, parent bytes, author directions, earlier feedback and chosen route overrides. Provider rewrites remain separate from submitted prompts. New reflection records measure this complete canonical context at queue time; the existing 200,000-byte context and 4 MB lineage-read limits durably defer large contexts without truncation or losing hero approval. Existing immutable reflection records are not rewritten. If an older record's captured byte count does not match the expanded verified shape, admission cancels before dispatch rather than silently replacing its context.

## Publishing helpers

`assertCurrentVisuals(ctx,post)` is called by the coordinator's final post approval. `buildPublicationVisuals(ctx,post)` provides the same gate and exact asset manifest inside the coordinator's single publication snapshot. Any post with visual state must select an approved hero; pre-feature posts without state remain on the existing legacy metadata path. `onArticleChange(ctx,post,{title,content})` flags substantive or unknown changes. Only exact text, narrow intra-line whitespace, and a small explicitly verified spelling normalization are automatic copy edits; markdown line/paragraph/list boundaries and code/link/URL/HTML changes retain their exact structure; other copy edits conservatively require relevance confirmation.

Meaningful selected-scene/version, image completion, export, alt/context approval, and relevance changes clear final post approval. Identical repeated approvals preserve it. Dates/scheduling fields remain untouched.

## Storage and transaction bounds

Input serialization uses measured UTF-8 bytes, not character counts: at most 200,000 input bytes and 750,000 complete attempt/version document bytes. Completion arguments are bounded to 100,000 bytes; receipt strings to 16,000 bytes; reviewed article signatures to 75,000 bytes; scene fields and each scene's 24,000-byte envelope are bounded. Full canonical signatures remain exact within those limits. Oversized initial requests fail before state or attempt persistence.

Reflection context above 200,000 canonical UTF-8 bytes records `reflection-context-too-large` and remains queued without admission. A reflection's serialized request input above 200,000 bytes records `reflection-input-too-large` with a minimal non-dispatchable input referencing the immutable records; exact reviewed article and original inputs remain on the reflection and versions. Either condition preserves valid hero approval. Traversal is bounded to 64 versions and roughly 4 MB of version documents; oversized/invalid legacy chains record durable deferral with a known owned lineage suffix. Only read-limit or length deferrals retain an owned `lineageResumeVersionId`; missing/foreign/invalid lineage never exposes a continuation ID. All original prompts/feedback remain on immutable versions and the parent chain; no automatic summarization or lossy replacement occurs. Such incomplete lineage is never dispatched. This is a deferral frontier, not completed reflection processing.

Final approval invalidation reads every approved publishing intent through its post/approval index, up to 512 within one atomic transition. A single bounded `take(513)` detects overflow without multiple paginations. More records block author transitions explicitly, so no older approved intent silently survives; charged image completion instead retains its cost/output and defers selection. An audit records invalidation; scheduling fields and protected lifecycle statuses are preserved.

Future dispatchers must persist the returned claim before provider I/O, retain uncertain outcomes, and never retry them. If trusted completion validation rejects a paid output, call `failAttempt` with its honest retained usage receipt; do not discard the charge. No dispatcher or paid qualification is supplied here.
