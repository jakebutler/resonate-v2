- **The blog channel is genuinely activation-ready.** `app/api/publish/route.ts` calls `createBlogPostPR`; a real PR (corvo-labs-dot-com#54) was created in the C.2 smoke. Publish timing = PR merge on the blog repo; the scheduled date lands in MDX frontmatter.
- **The LinkedIn channel is NOT activation-ready — this is the one remaining build item.** The UI's only submit path is the mock (`components/PersistedPublishingPanel.tsx:549` → `submitMockProvider`). Setting `BUFFER_LIVE_SUBMISSION=approved` alone changes nothing the operator can reach.

- **Open issues:** #1 (PRD — delivered), #21 (roadmap — complete except LinkedIn submission wiring), #44 (12-step HITL production eval — never executed; script at `docs/eval/reviewable-parity-script.md` is already updated for post-cutover routes), #45 (Marketing Director `/campaigns` — large net-new feature, defer).
- **Env risks:** `GITHUB_TOKEN` in Vercel is 44+ days old (expiry unverified). `BUFFER_LIVE_SUBMISSION`/`ZERNIO_LIVE_SUBMISSION` absent from prod (expected while gated). AI-authoring env must be verified: `PIONEER_API_KEY` absent → draft routes silently return canned fallback text; `CORTEX_API_KEY`/`OPENAI_API_KEY` absent → composer chat hard-fails (`lib/cortex.ts:48`). Both PIONEER_* and CORTEX_* exist in Vercel prod env list; whether they're live/valid is unverified.

**Bottom line:** Blog publishing is verification-and-activation. LinkedIn publishing needs one real build slice (Buffer submission wiring) before it works from the app — or a deliberate descope to manual copy-into-Buffer for the first series.

## Phase 3 — Build + activate LinkedIn submission (build slice; user decision gates go-live)

**This is build work, not a flag flip (audit F1).** Scope:

1. **Wire real submission (implementation, ~0.5–1.5 days incl. tests):**
   - New Convex action (or API route) that assembles the submission payload from the approved post + `platformSettings`, calls `bufferProviderAdapter.submit()` under the existing `BUFFER_LIVE_SUBMISSION` gate, and records `v2PublishAttempts` + audit events with sanitized responses — mirroring the mock path's bookkeeping.
   - UI: branch `handleSubmit` in `PersistedPublishingPanel` — live submit for approved LinkedIn posts when the gate is on, mock/simulate clearly labeled otherwise. Human-gated retry only (A.1.2). Cancel path wired to `recordCancelOrUnpublishIntent`.
   - Tests: approval-gated (unapproved never submits), gate-off falls back to labeled simulate, submit records attempt + provider post id, cancel round-trip. Reuse the provider contract suite.
   - **Code review: Fable** (touches provider submission + approval gating — highest-rigor tier per the model-routing policy below).
2. **User decision:** approve live Buffer submission to the Corvo Labs LinkedIn queue.
3. Set `BUFFER_LIVE_SUBMISSION=approved` in Vercel prod; `npx vercel deploy --prod`.
4. **Prove it through the app (audit amendment 2):** author a throwaway LinkedIn post in the composer → approve → submit → verify it appears in the real Buffer queue → cancel → verify removal + attempts/audit rows. Append sanitized proof to `docs/live-provider-validation.md`.
5. Leave `ZERNIO_LIVE_SUBMISSION` unset (Reddit deferred; same activation pattern later).

**Fallback if the user wants to publish before this slice lands:** author LinkedIn variants in-app and paste them into Buffer manually. Explicitly a stopgap; the app does not queue to Buffer until this phase completes.

**Exit:** a post authored in Resonate reaches the real Buffer queue and is cancelled, with attempts + audit recorded.

## Appendix — Independent audit record (Opus, 2026-07-19)

> Verdict: **Not sound to execute as written for the LinkedIn half of the goal** (rev 1). The plan's premise — "verification-and-activation, not build" — holds for the blog/GitHub-PR channel but is false for LinkedIn/Buffer. Amended in rev 2 above.

**Findings (all incorporated in rev 2):**

- **F1 (BLOCKER, confirmed by Fable re-verification):** No in-app path submits to Buffer. `PersistedPublishingPanel.tsx:548-555` calls `submitMockProvider` only; `bufferProviderAdapter.submit()` is invoked solely by tests and `scripts/buffer-live-validation.mjs`. `docs/live-provider-validation.md` states social post creation is unavailable until submission wiring is implemented. → Phase 3 rewritten as a build slice.
- **F2 (HIGH):** #44's step 9 never submits to Buffer; a green eval doesn't prove LinkedIn. → Phase 2 note + Phase 3.4 in-app proof step.
- **F3 (HIGH):** No Convex crons/scheduler exists; "schedule" is calendar metadata only. Blog timing = PR merge; LinkedIn timing = Buffer-native. → Scheduling language corrected throughout.
- **F4 (HIGH):** AI authoring env unchecked: missing `PIONEER_API_KEY` yields silent deterministic fallback drafts (`app/api/generate-draft/route.ts:75-83`); missing `CORTEX_API_KEY`/`OPENAI_API_KEY` throws in `lib/cortex.ts:48-53`. → Added to Phase 2.1.
- **F5 (MEDIUM):** Closing #21 unqualified would misrepresent LinkedIn as done (child #13 closed while submission unwired). → Phase 4 amended.
- **F6 (LOW):** Deferring #45 and Zernio/Reddit is sound. → Unchanged.

**Confirmed by audit:** issue states (#1/#21/#44/#45 open; #2–#19, #34–#43 closed); no parity-run doc exists; blog PR path wired end-to-end (`app/api/publish/route.ts:98`); eval script already uses post-cutover routes; gating logic at `lib/providerAdapters.ts:274-281, 725-732`. **Not verifiable read-only:** Vercel env values/freshness, prod Convex drift, live alias mapping.
